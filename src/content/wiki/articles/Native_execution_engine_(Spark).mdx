In [Apache Spark](/wiki/Apache_Spark), a **native execution engine** is a component that runs the physical operators of a Spark SQL or DataFrame query as vectorized, columnar code compiled to machine code (usually C++ or Rust) instead of as Java bytecode generated by Spark's whole-stage code generation in the Java virtual machine (JVM). Spark still parses, optimizes and schedules the query; the native engine replaces only the execution of the operators it supports and hands the rest back to Spark. Open source examples are [Apache Gluten](/wiki/Apache_Gluten) and [Apache DataFusion Comet](/wiki/Apache_DataFusion_Comet); Databricks Photon is a proprietary example.[^glreadme][^cmreadme]

## What is a native execution engine?

Apache Spark's own engine runs in the JVM. Since Spark 2.0.0, whole-stage code generation, part of [Project Tungsten](/wiki/Project_Tungsten), compiles chains of operators into one generated Java function per stage; it is on by default through `spark.sql.codegen.wholeStage` in Spark 4.3.0.[^sqlconf][^wscg]

A native execution engine for Spark takes the physical plan that Spark has already chosen, converts the supported part of it into a plan for a native library, and runs that part outside the JVM on columnar batches. Apache Gluten converts the plan to Substrait and passes it through the Java Native Interface (JNI) to [Velox](/wiki/Velox) or ClickHouse.[^glreadme] Apache DataFusion Comet serializes it in its own Protocol Buffers format and runs it with Apache DataFusion, written in Rust.[^cmp]

## How does a native engine plug into Apache Spark?

Open source native engines attach to Apache Spark through its public extension points. Both Gluten and Comet are enabled with the `spark.plugins` setting, turn on Spark off-heap memory (`spark.memory.offHeap.enabled`, which is false by default), and replace `spark.shuffle.manager` with a columnar shuffle manager so that data stays columnar between stages.[^glreadme][^cmreadme][^sparkconf] Application code, SQL and DataFrame queries do not change.

## What runs natively and what falls back?

A native execution engine for Spark runs only the operators and expressions it supports. Everything else falls back to Spark's JVM operators, and the engine inserts conversions between its columnar format and Spark's row format at each boundary. Gluten calls these ColumnarToRow and RowToColumnar transitions.[^glreadme] Comet falls back at the level of a query stage: if a stage contains an unsupported operator, the stage runs in Spark.[^cmops] Photon also falls back to the Spark runtime for operations it does not support.[^photondocs] Because each transition has a cost, the share of a plan that runs natively matters as much as the speed of the native operators.

## What about Photon?

Photon is the vectorized query engine built by Databricks. Databricks describes Photon as a proprietary part of the Databricks Runtime that is not part of open source Apache Spark and is not distributed with it.[^photonoss] Databricks described it in the paper "Photon: A Fast Query Engine for Lakehouse Systems", published in the proceedings of the ACM SIGMOD 2022 conference (June 2022).[^paper] The Databricks documentation states that Photon replaces the JVM-based Spark SQL execution engine with a native C++ runtime for supported operations, keeps Spark's Catalyst optimizer for planning, and is compatible with Apache Spark APIs.[^photondocs]

## What a native execution engine is not

- **Not Project Tungsten.** [Project Tungsten](/wiki/Project_Tungsten) made Spark's JVM execution faster with binary rows, managed memory and generated Java code; it does not leave the JVM. Native engines replace those JVM operators.[^wscg]
- **Not GPU acceleration.** GPU plugins, such as the NVIDIA cuDF plugin for Apache Spark (formerly the RAPIDS Accelerator for Apache Spark), also replace Spark operators, but run them on GPUs through the cuDF libraries.[^cudf] See [GPU acceleration in Spark](/wiki/GPU_acceleration_in_Spark).
- **Not a separate query engine.** A native execution engine for Spark has no SQL parser or scheduler of its own in this setup; Spark plans and distributes the work.[^glreadme]
