**MLlib** is the machine learning library of [Apache Spark](/wiki/Apache_Spark). It provides distributed learning algorithms (classification, regression, clustering, collaborative filtering), feature transformations, ML Pipelines, model persistence and utilities such as linear algebra and statistics.[^guide] MLlib has two APIs: the DataFrame-based API in the `spark.ml` package, which is the primary API, and the older [RDD](/wiki/RDD)-based API in the `spark.mllib` package, which has been in maintenance mode since Spark 2.0.[^guide] Neither API, and not MLlib as a whole, is deprecated.[^guide]

## Two APIs

|  | `spark.ml` (DataFrame-based) | `spark.mllib` (RDD-based) |
| --- | --- | --- |
| Status in Spark 4.3.0 | Primary API; new features go here | Maintenance mode since Spark 2.0: bug fixes only, no new features |
| Data type | [DataFrame](/wiki/DataFrame) with feature vector columns | [RDD](/wiki/RDD) of objects such as `LabeledPoint` |
| Building blocks | Estimators, transformers, evaluators and pipelines | Algorithm objects with `train` methods |
| Linear algebra types | `org.apache.spark.ml.linalg` | `org.apache.spark.mllib.linalg` |
| Spark Connect | Supported from Spark 4.0.0 (Python) | Not supported, because Connect has no RDD API |

Sources: the MLlib guide and migration guide,[^guide][^migration] the Spark Connect overview[^connect] and SPARK-50812.[^jira50812]

The MLlib guide gives the reasons for the move to DataFrames: a friendlier API, Spark data sources, SQL queries, the Catalyst and Tungsten optimizations, one API across languages, and practical ML Pipelines, especially for feature transformations.[^guide]

## What "Spark ML" means

"Spark ML" is not an official name. The MLlib guide says it is sometimes used for the DataFrame-based API, because of the `org.apache.spark.ml` package name and the early term "Spark ML Pipelines". The official name of the library, covering both APIs, is MLlib.[^guide] In code, `pyspark.ml` is the DataFrame-based API and `pyspark.mllib` is the RDD-based one.

## History

MLlib was introduced in Spark 0.8.0 as a library of machine learning and optimization algorithms, developed with the UC Berkeley MLbase project.[^n1] Spark 1.2.0 previewed a new set of machine learning APIs in a package called `spark.ml`, built around learning pipelines and using Spark SQL's SchemaRDD (the predecessor of the DataFrame) to represent datasets.[^n2] In Spark 2.0.0 the DataFrame-based API became the primary API and the RDD-based API entered maintenance mode.[^r200] The Spark 2.x versions of the MLlib guide said the RDD-based API was expected to be removed in Spark 3.0; that sentence was dropped from the guide for the 3.0 release, and the RDD-based API is still part of Spark 4.3.0.[^n3][^jira30934] See [spark.mllib (RDD-based API)](/wiki/Spark.mllib_(RDD-based_API)) for what was removed from that package.

## MLlib and Spark Connect

Spark has had two attempts at machine learning over [Spark Connect](/wiki/Spark_Connect).

- **`pyspark.ml.connect` (Spark 3.5.0).** Spark 3.5.0 added a separate package, `pyspark.ml.connect`, with its own estimators, transformers, pipelines and cross-validation for Connect clients.[^n4] This package was deprecated in Spark 4.0.0 (SPARK-50828); its classes carry a `deprecated:: 4.0.0` note at the v4.3.0 tag.[^jira50828][^n5]
- **`pyspark.ml` on Connect (Spark 4.0.0).** Spark 4.0.0 made the regular `pyspark.ml` API work on Spark Connect (SPARK-50812), listed as "ML on Spark Connect" in the release highlights.[^r400][^jira50812] When the session is remote, `pyspark.ml` sends fit and transform calls to the Connect server, which runs the Scala implementation in its ML handler.[^n6][^n7]

The RDD-based `spark.mllib` API cannot run over Connect, because Connect does not support RDDs or the `SparkContext`.[^connect]

## Example

A DataFrame-based pipeline in PySpark. The same code runs in a classic session and, from Spark 4.0.0, in a Spark Connect session.

```python
from pyspark.ml import Pipeline
from pyspark.ml.classification import LogisticRegression
from pyspark.ml.feature import VectorAssembler

train = spark.createDataFrame(
    [(0.0, 1.1, 0.1), (1.0, 2.0, 1.0), (0.0, 1.3, -0.5), (1.0, 2.2, 1.5)],
    ["label", "x1", "x2"])

pipeline = Pipeline(stages=[
    VectorAssembler(inputCols=["x1", "x2"], outputCol="features"),
    LogisticRegression(maxIter=10),
])
model = pipeline.fit(train)
model.transform(train).select("label", "prediction").show()
```
