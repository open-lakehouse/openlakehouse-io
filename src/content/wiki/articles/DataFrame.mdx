A **DataFrame** is a table-like data structure made of named columns, each with a data type, and rows. In [Apache Spark](/wiki/Apache_Spark), a DataFrame is a distributed collection of rows organized into named columns, conceptually equivalent to a table in a relational database, and it is the main API of Spark SQL in Python, Scala, Java and R.[^guide] The same word names the in-memory, single-process tables of pandas and Polars, which share the tabular shape but differ in where the data lives and when work is done. This page explains the Spark DataFrame and compares it with those two.

## What is a DataFrame in Apache Spark?

A Spark DataFrame is a [Dataset](/wiki/Dataset_(Spark)) organized into named columns. In Scala, `DataFrame` is a type alias of `Dataset[Row]`; in Java it is written `Dataset<Row>`; Python and R have only the DataFrame.[^guide] DataFrames can be built from files, tables, external databases or existing [RDDs](/wiki/RDD).[^guide]

A Spark DataFrame does not hold its data in the driver. Internally it represents a logical plan that describes how to produce the data. Transformations such as `select`, `filter` and `groupBy` return new DataFrames, and nothing runs until an action such as `count`, `show` or a write is called. Then Spark's optimizer turns the logical plan into a physical plan that runs in parallel on [executors](/wiki/Executor); `explain()` shows both plans.[^dataset]

With [Spark Connect](/wiki/Spark_Connect), a PySpark or Scala DataFrame lives in a thin client: the client sends unresolved logical plans to the Spark server over gRPC and receives results as Apache Arrow batches.[^connect]

```python
from pyspark.sql import SparkSession, functions as F

spark = SparkSession.builder.getOrCreate()

orders = spark.read.parquet("s3://bucket/orders/")      # no data is read yet
daily = (orders
         .filter(F.col("status") == "shipped")
         .groupBy("order_date")
         .agg(F.sum("amount").alias("revenue")))         # still only a plan

daily.explain()   # prints the physical plan
daily.show(5)     # action: Spark runs the job on the executors
```

The same query in Spark SQL:

```sql
SELECT order_date, SUM(amount) AS revenue
FROM parquet.`s3://bucket/orders/`
WHERE status = 'shipped'
GROUP BY order_date;
```

## How do Spark DataFrames work with table formats?

In an open lakehouse, Spark DataFrames are the usual way to read and write tables in [Delta Lake](/wiki/Delta_Lake), [Apache Iceberg](/wiki/Apache_Iceberg) and [Apache Parquet](/wiki/Apache_Parquet) files. For example, the Delta Lake quick start writes a DataFrame with `data.write.format("delta").save(path)` and reads it back with `spark.read.format("delta").load(path)`.[^n1]

## Spark DataFrame vs pandas vs Polars

|  | Apache Spark DataFrame | pandas DataFrame | Polars DataFrame |
| --- | --- | --- | --- |
| Where the data lives | Partitions spread across executors in a cluster; the DataFrame object is a plan[^dataset] | In memory; pandas is designed for in-memory analytics[^pdscale] | In memory on one machine[^plhome] |
| Evaluation | Lazy: transformations build a plan, actions run it[^dataset] | Eager[^plpandas] | Eager `DataFrame` and lazy `LazyFrame`; in many cases the eager API calls the lazy engine[^pllazy] |
| Query optimizer | Spark's query optimizer turns the logical plan into a physical plan[^dataset] | None (operations run as called)[^plpandas] | Query planner with predicate and projection pushdown in lazy mode[^pllazy] |
| Parallelism | Tasks across many executors and machines[^guide] | Not built in; the pandas docs point to other libraries for parallel and distributed work[^pdscale] | Multi-threaded across the CPU cores of one machine[^plhome] |
| Row index | No row labels | Labeled row and column axes[^pdapi] | None; rows are addressed by integer position[^plpandas] |
| Memory format | A binary internal format produced by encoders[^dataset]; Arrow for data exchange with Python[^arrow] | NumPy arrays by default; columns can be backed by PyArrow[^pdarrow][^plpandas] | Arrow memory specification, with its own compute implementation[^plhome][^plpandas] |
| Languages | Python, Scala, Java, R, SQL[^guide] | Python | Core in Rust; Python, R and NodeJS APIs[^plhome] |
| Latest version (checked 2026-11-23) | PySpark 4.3.0[^pypi] | pandas 3.1.1[^n2] | Polars 2.1.0[^n3] |

## How do you move data between Spark, pandas and Arrow?

`DataFrame.toPandas()` collects a Spark DataFrame to the driver as a pandas DataFrame, and `SparkSession.createDataFrame()` accepts a pandas DataFrame. Both use Apache Arrow when `spark.sql.execution.arrow.pyspark.enabled` is true, and since Spark 4.2 it is true by default.[^arrow][^n4] Since Spark 4.0, `DataFrame.toArrow()` returns a PyArrow Table and `createDataFrame()` accepts one; a Polars DataFrame can be exchanged through Arrow this way.[^arrow][^plhome]

Both `toPandas()` and `toArrow()` bring every row to the driver, so the Spark documentation advises using them only on a small subset of the data.[^arrow]

The pandas API on Spark (`pyspark.pandas`), added in Spark 3.2.0, offers a pandas-like API whose operations run on Spark DataFrames.[^n5]

## History

Spark 1.3.0 added the DataFrame API, described in the release notes as an evolution of the RDD API with named fields and schema information, for Python, Scala and Java.[^n6] It replaced `SchemaRDD`.[^migration] Spark 2.0.0 unified DataFrame and Dataset in Scala and Java, making DataFrame a type alias for `Dataset[Row]`.[^n7]
