A **Spark Connect client** is a library that lets an application use [Apache Spark](/wiki/Apache_Spark) remotely through the [Spark Connect](/wiki/Spark_Connect) protocol: it builds unresolved logical plans as Protocol Buffers messages, sends them to a Spark Connect server over gRPC, and decodes the results, which come back as Apache Arrow record batches.[^overview] A Spark Connect client runs in its own process, separate from the Spark driver, and does not reach into the driver JVM; the PySpark client does not use Py4J.[^overview] The `pyspark-client` package leaves Py4J out and depends only on Python libraries such as `pyarrow` and `grpcio`, so it needs no local Spark JVM.[^clientsetup] Because the protocol is language-agnostic, a client can be written in any language with gRPC and Arrow support, and the Scala client (`spark-connect-client-jvm`) and the JDBC driver are themselves JVM libraries.[^overview][^mvnjdbc] The Apache Spark project ships Python and Scala clients and a JDBC driver, and maintains separate Go, Swift and Rust clients; other clients are community projects.

## What does a Spark Connect client do?

A Spark Connect client has three jobs. It turns DataFrame or SQL calls into a protobuf plan, manages a gRPC channel and session with the server, and turns Arrow batches into native values. The Spark documentation describes the protocol as language-agnostic, and the server runs every plan through the normal Spark optimizer and execution engine, so a query from a Go client and the same query from PySpark run the same way on the server.[^overview]

All official clients address the server with the same connection string format, `sc://host:port/;param=value`. The Spark Connect developer guidelines ask new clients to follow this format so that the user experience is the same in every language. The parameters include `token`, `use_ssl`, `user_id`, `user_agent`, `session_id` and gRPC keepalive settings, and the default port is 15002.[^connstr][^readme]

| Go client | [apache/spark-connect-go](https://github.com/apache/spark-connect-go) | Go | v0.1.0 (GitHub release, 17 June 2025)[^gorel] | "Highly experimental and should not be used in any production setting"; the Spark PMC reserves the right to withdraw it[^goreadme] | The `spark/sql` package has session, DataFrame, reader, writer, grouping, NA and statistics APIs, but no streaming or UDF API; last commit on `master` in August 2025[^gocommits][^gotree] |

| Rust client | [apache/spark-connect-rust](https://github.com/apache/spark-connect-rust); crate `apache-spark-connect`, PyPI `pyspark-client-rust` | Rust, with a Python wrapper | 4.3.0 (git tag and packages, 16 November 2026)[^crate][^rustpypi] | README claims full public-API parity with PySpark 4.3.0 for the Python wrapper; targets Spark 4.3.0 and later[^rustreadme][^rustcompat] | Native Rust API excludes APIs that need Python itself, such as pandas; UDFs are Rust functions compiled to WebAssembly[^rustdocs] |
| .NET client (community) | [GoEddie/spark-connect-dotnet](https://github.com/GoEddie/spark-connect-dotnet) | C# and other .NET languages | v4.0.0-build.41 (3 October 2026)[^dotnet] | Not an Apache project (MIT license)[^dotnet] | README says keeping up with new Spark versions is hard and advises users to be prepared to make their own gRPC calls for functions the library lacks[^dotnet] |
| JavaScript client (community) | [yaooqinn/spark.js](https://github.com/yaooqinn/spark.js); npm `@yaooqinn/spark.js` | TypeScript | v0.1.0 (git tag, January 2026)[^sparkjs] | "Experimental"; APIs may change without notice[^sparkjs] | Requires Spark 4.0 or later[^sparkjs] |

The Apache Spark download directory lists source releases of the Swift client but none of the Go or Rust clients.[^dist] The Rust client replaced an earlier community project, sjrusso8/spark-connect-rs, whose repository is now read-only and points to apache/spark-connect-rust.[^n1] The Rust repository also contains an unpublished, experimental Rust server frontend intended for local, trusted experiments.[^rustreadme]

## How is a client connected to a server?

In PySpark, the `pyspark-client` package contains only the Spark Connect client, and `SparkSession.builder.remote()` takes the connection string.[^overview] The following example connects over TLS with a bearer token; according to the connection string reference, setting `token` also enables TLS.[^connstr]

```python
# pip install pyspark-client==4.3.0
from pyspark.sql import SparkSession

spark = (
    SparkSession.builder
    .remote("sc://spark.example.com:443/;use_ssl=true;token=MY_TOKEN;user_agent=etl_app")
    .getOrCreate()
)
print(spark.version)
spark.sql("SELECT 1 AS ok").show()
```

The same string can be set in the `SPARK_REMOTE` environment variable. The Swift README states that its client also reads `SPARK_REMOTE`, and the Rust and JavaScript clients take an `sc://` address in their builders.[^overview][^swiftreadme][^rustreadme][^sparkjs]

## Spark Connect client vs classic Spark application

A Spark Connect client differs from a classic PySpark or Scala application because it runs outside the driver:[^overview]

|  | Spark Connect client | Classic Spark application |
| --- | --- | --- |
| Process | Separate from the driver; talks to it over gRPC | Runs inside the driver process (Py4J bridge for PySpark) |
| `SparkContext` and RDDs | Not available | Available |
| Cluster-wide and static configuration | Not accessible; session settings only | Accessible |
| Dependencies | Client library only; server upgraded independently | Shares the driver's process and dependencies |
