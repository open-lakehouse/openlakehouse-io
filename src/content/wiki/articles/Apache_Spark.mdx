**Apache Spark** is an open source, distributed engine for large-scale data processing, with high-level APIs in Java, Scala, Python and R and an optimized engine that runs general execution graphs.[^docs-index] Spark runs batch queries, SQL, stream processing and machine learning on one engine, on a single machine or on a cluster. In an [open lakehouse](/wiki/Open_lakehouse), Spark is one of the engines that reads and writes [open table formats](/wiki/Open_table_format) such as [Apache Iceberg](/wiki/Apache_Iceberg) and [Delta Lake](/wiki/Delta_Lake) through a shared [data catalog](/wiki/Data_catalog).

## Architecture

A Spark application runs as a set of independent processes on a cluster. The **driver** program holds the `SparkContext` (wrapped by `SparkSession` in the DataFrame API) and plans the work. The driver connects to a **cluster manager**, which allocates resources, and then obtains **executors**: processes on worker nodes that run computations and store data for the application. The driver sends application code and then **tasks** to the executors.[^cluster]

Each Spark application gets its own executor processes, which stay up for the whole application. This isolates applications from one another, but it also means two Spark applications cannot share in-memory data without writing it to external storage.[^cluster]

### Execution model

Spark evaluates transformations lazily. A transformation such as a filter or a join only records how a dataset is derived; Spark computes it when an **action**, such as `collect` or a write, needs a result. The Spark documentation explains that this lets Spark run more efficiently, for example by returning only the result of a final aggregation to the driver instead of a large intermediate dataset.[^n1]

A Spark **job** is a parallel computation that Spark starts in response to an action. Spark divides each job into **stages**, sets of tasks that depend on one another in a similar way to the map and reduce stages of MapReduce, and sends each **task** to one executor.[^cluster]

The **deploy mode** sets where the driver runs. In cluster mode, the driver is launched inside the cluster; in client mode, the process that submits the application runs the driver outside the cluster.[^cluster]

### Cluster managers

Spark 4.3 supports three cluster managers: Spark's own **standalone** manager, **Hadoop YARN** and **Kubernetes**. Applications are submitted to any of them with the `spark-submit` script. Each driver also serves a web UI, by default on port 4040.[^cluster] The project also maintains a separate Spark Kubernetes Operator for running Spark applications and clusters through Kubernetes custom resources.[^docs-index]

## APIs and libraries

Spark exposes several libraries on top of its core engine:[^docs-index]

- **Spark SQL and DataFrames**: structured data processing through SQL or the DataFrame and Dataset APIs, optimized by the Catalyst query optimizer.[^r200][^n2]
- **[Structured Streaming](/wiki/Structured_Streaming)**: stream processing built on the Spark SQL engine, using the same DataFrame operations as batch queries.
- **MLlib**: a library of machine learning algorithms and pipelines.[^n3]
- **pandas API on Spark**: a pandas-compatible API that runs on Spark. It was added in Spark 3.2.0.[^r320]
- **GraphX**: graph processing.[^docs-index]

The R API (SparkR) is marked as deprecated in the Spark 4.3 documentation. Spark 4.3 runs on Java 17, 21 or 25, Scala 2.13 and Python 3.11 or later.[^docs-index]

A short PySpark example that reads a table and aggregates it:

```python
from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.appName("example").getOrCreate()

orders = spark.read.table("sales.orders")
daily = orders.groupBy("order_date").agg(F.sum("amount").alias("revenue"))
daily.write.mode("overwrite").saveAsTable("sales.daily_revenue")
```

## Spark Connect

<Hatnote>Main article: [Spark Connect](/wiki/Spark_Connect)</Hatnote>

Spark Connect is a client-server protocol, introduced in Spark 3.4, in which a thin client sends unresolved logical plans to a Spark server over gRPC and receives results as Apache Arrow batches.[^connect] The client does not run inside the driver process, so applications can run in IDEs, notebooks and services away from the cluster. Besides the Python and Scala clients in the main repository, the Spark project maintains separate Spark Connect clients for Go, Rust and Swift.[^n4][^n5][^n6] Spark 4.0 added a lightweight Python client package (`pyspark-client`) and the `spark.api.mode` setting, which lets a classic application switch to Spark Connect.[^r400]

## Spark Declarative Pipelines

<Hatnote>Main article: [Spark Declarative Pipelines](/wiki/Spark_Declarative_Pipelines)</Hatnote>

Spark Declarative Pipelines (SDP), added in Spark 4.1.0, is a framework in which a user declares datasets (streaming tables, materialized views and temporary views) and the flows that fill them, and Spark works out the dependency order, parallelism, checkpoints and retries.[^r410] Pipelines are run with the `spark-pipelines` command line tool.[^n7]

## History

Spark started in 2009 as a research project at the AMPLab of the University of California, Berkeley, and was open sourced in early 2010. The project moved to the Apache Software Foundation in 2013.[^history] The ASF announced on 27 February 2014 that Spark had graduated from the Apache Incubator to become a top-level project.[^n8]

## Use in an open lakehouse

Spark reads and writes lakehouse tables through table format connectors and its catalog plugin API. A catalog is registered by setting Spark properties under `spark.sql.catalog.<name>`; the [Apache Iceberg](/wiki/Apache_Iceberg) documentation, for example, shows a catalog of type `rest` that talks to an [Iceberg REST catalog](/wiki/Iceberg_REST_catalog).[^n12] [Delta Lake](/wiki/Delta_Lake) is enabled with the `io.delta.sql.DeltaSparkSessionExtension` SQL extension and the `DeltaCatalog` session catalog.[^n13]

Because the table data sits in open formats such as [Apache Parquet](/wiki/Apache_Parquet) and the metadata sits in a catalog such as [Unity Catalog](/wiki/Unity_Catalog) or [Apache Polaris](/wiki/Apache_Polaris), the same tables Spark writes can be queried by other engines, for example [Trino](/wiki/Trino) or [DuckDB](/wiki/DuckDB). Spark is commonly used for the ingestion and transformation layers of a [medallion architecture](/wiki/Medallion_architecture), with [Apache Airflow](/wiki/Apache_Airflow) or Spark Declarative Pipelines deciding when each step runs.
