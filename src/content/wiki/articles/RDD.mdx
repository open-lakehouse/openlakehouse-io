In [Apache Spark](/wiki/Apache_Spark), a **resilient distributed dataset** (**RDD**) is an immutable collection of elements split into partitions across the nodes of a cluster, which can be processed in parallel and is rebuilt from its lineage when a partition is lost.[^guide] The RDD was Spark's main programming interface before Spark 2.0; since then the Spark documentation recommends the [Dataset](/wiki/Dataset_(Spark)) and [DataFrame](/wiki/DataFrame) APIs, which run through the Catalyst optimizer, while stating that the RDD interface is still supported.[^quick] RDDs still underlie older libraries such as [GraphX](/wiki/GraphX) and [Spark Streaming (DStreams)](/wiki/Spark_Streaming_(DStreams)), but they are not available to [Spark Connect](/wiki/Spark_Connect) clients.[^connect]

## Status

The RDD API is not deprecated. The `RDD` class at the v4.3.0 tag of Spark carries no deprecation annotation, and the Spark 4.0.0 to 4.3.0 release notes list no deprecation of the RDD API.[^rddscala][^r400] Only single methods are deprecated; for example, PySpark's `mapPartitionsWithSplit` is deprecated in favor of `mapPartitionsWithIndex`.[^pyrdd]

The practical limit is Spark Connect. The Spark Connect documentation lists `SparkContext` and RDD as unsupported for both Python and Scala clients.[^connect] In the PySpark Connect client, `DataFrame.rdd` raises a not-implemented error.[^n1] Code that uses RDDs therefore needs a classic Spark application, which is the default: `spark.api.mode` defaults to `classic` in Spark 4.3.0.[^n2]

## How it works

An RDD is created from a file in a Hadoop-supported file system, from a collection in the driver program, or by transforming another RDD.[^guide] The design was described in the 2012 paper *Resilient Distributed Datasets: A Fault-Tolerant Abstraction for In-Memory Cluster Computing* by Matei Zaharia and others at the University of California, Berkeley.[^paper]

RDDs support two kinds of operations. **Transformations**, such as `map` and `filter`, return a new RDD. **Actions**, such as `reduce` and `collect`, return a value to the driver. Transformations are lazy: Spark records them and computes nothing until an action needs a result.[^guide] Each RDD is divided into [partitions](/wiki/Partition), and the executors process one partition per task.

Fault tolerance comes from **lineage**, the record of the transformations that built an RDD. If a partition is lost, Spark recomputes it from that record instead of restoring a replica.[^guide][^paper] An RDD can be kept for reuse with `persist()` or `cache()`; `cache()` uses the default storage level `MEMORY_ONLY`, and other storage levels keep the data serialized, on disk or replicated.[^guide]

## RDD compared with DataFrame and Dataset

|  | RDD | DataFrame | Dataset |
| --- | --- | --- | --- |
| Element type | Any JVM or Python object, opaque to Spark | Rows with a schema of named, typed columns | Typed JVM objects with an encoder (Scala and Java only) |
| Optimization | None by Spark SQL; the user's functions run as written | Spark SQL uses the schema to optimize the query | Spark SQL uses the schema to optimize the query |
| Languages | Scala, Java, Python | Scala, Java, Python, R | Scala, Java |
| Spark Connect | Not supported | Supported | Supported in the Scala client |

The Spark quick start recommends the Dataset over the RDD because it is strongly typed like an RDD but has better performance.[^quick] The Spark SQL guide describes the Dataset, added in Spark 1.6, as combining the benefits of RDDs (strong typing and lambda functions) with Spark SQL's optimized execution engine, and a DataFrame as a Dataset organized into named columns. Python and R have no Dataset API but use DataFrames.[^n3][^connect]

## Where RDDs still appear

- **Older libraries.** [GraphX](/wiki/GraphX) represents graphs as RDDs, and a DStream in [Spark Streaming (DStreams)](/wiki/Spark_Streaming_(DStreams)) is a sequence of RDDs.[^n4] The RDD-based machine learning package, [spark.mllib (RDD-based API)](/wiki/Spark.mllib_(RDD-based_API)), is in maintenance mode.
- **Low-level control.** The RDD API gives direct control over partitioning and over functions applied to each element, which some programs use for work that does not fit a tabular schema.
- **Execution internals.** DataFrame and SQL queries also end up as RDDs: in Spark 4.3.0, executing a physical plan node (`SparkPlan.execute()`) returns an RDD of internal rows.[^n5]

## Example

A word count with the RDD API in PySpark, in classic mode:

```python
from pyspark.sql import SparkSession

spark = SparkSession.builder.master("local[*]").getOrCreate()
sc = spark.sparkContext

lines = sc.parallelize(["a b", "b c", "c"])
counts = (lines.flatMap(lambda line: line.split())
               .map(lambda word: (word, 1))
               .reduceByKey(lambda a, b: a + b))

print(sorted(counts.collect()))  # [('a', 1), ('b', 2), ('c', 2)]
```

The same result with the DataFrame API also runs through Spark Connect:

```python
from pyspark.sql import functions as F

df = spark.createDataFrame([("a b",), ("b c",), ("c",)], ["line"])
df.select(F.explode(F.split("line", " ")).alias("word")).groupBy("word").count().show()
```
