**Project Nessie** is an open source transactional [data catalog](/wiki/Data_catalog) for data lakes that versions table metadata with Git-like commits, branches and tags.[^readme] A change to several tables can be made on a branch and published with one merge, so readers see all of the changes or none of them.[^tx] Nessie works with [Apache Iceberg](/wiki/Apache_Iceberg) tables and is reached through its own API or through the [Iceberg REST catalog](/wiki/Iceberg_REST_catalog) API.[^readme][^rest]

## How it works

Nessie keeps a commit log of catalog changes, not of data files. Each commit records the operations it made, a timestamp and the user, and a single commit can change many tables at once.[^tx] For an Iceberg table, the catalog entry points to the table's current metadata; the data and metadata files stay in object storage.

- **Branches** are named, movable pointers to commits. Work done on a branch is invisible on `main` until it is merged.[^tx]
- **Tags** are named references to a fixed commit, used to pin a consistent state of many tables.[^guides]
- **Merges** publish a series of commits from one branch to another as one consistent view, which is how Nessie gives cross-table visibility to engines that have no multi-table transactions of their own.[^tx]

The transactions guide describes three optimistic isolation levels (read committed, repeated read and serializable), with conflicts detected per table; pessimistic locking is not available.[^tx] Nessie stores its commit log in a pluggable version store; the configuration reference covers JDBC, RocksDB, Cassandra, DynamoDB, MongoDB, Bigtable and in-memory stores.[^config]

## How engines connect

Engines reach Nessie in two ways.

|  | Nessie catalog client | Iceberg REST API |
| --- | --- | --- |
| Endpoint | Nessie's own REST API | `/iceberg` on the Nessie server (port 19120 in the default Docker image)[^rest][^readme] |
| Client side | Iceberg's `NessieCatalog` (catalog type `nessie`); Trino's `nessie` Iceberg catalog type[^icebergcat][^n1] | Any Iceberg REST client |
| Choosing a branch | A client property naming the reference | The branch or tag name in the URI, with a mandatory `\|` before the warehouse name, for example `/iceberg/experiments\|sales`[^rest] |
| Maturity | The original integration | Added in Nessie 0.90.2 (June 2024) as beta;[^changelog] the current guide calls it experimental[^rest] |

With the Iceberg REST API, Nessie also manages table locations and vends storage credentials; the guide requires at least one object store and one warehouse to be configured, and notes that some storage integrations are still experimental.[^rest]

## Status

Nessie is an active project. Its latest release is 0.110.1, published on 21 November 2026, and the 0.x version numbers continue; no release marks the project or its server as deprecated.[^releases] Individual parts have been deprecated inside the project, for example the older JDBC, Cassandra and MongoDB version store types in favor of their `JDBC2`, `CASSANDRA2` and `MONGODB2` replacements.[^changelog]

On 2 August 2024, after Snowflake open-sourced the Polaris catalog, the Nessie project wrote that the intent is to contribute Nessie's capabilities, such as catalog-level versioning, Git-like semantics and multi-table transactions, to [Apache Polaris](/wiki/Apache_Polaris).[^polaris] The post did not announce an end date for Nessie, and Nessie releases have continued since.[^polaris][^releases]

## History

Dremio announced Project Nessie on 1 October 2020; the announcement by Jacques Nadeau said a small team at Dremio had spent more than a year building it.[^n2] In October 2024 Dremio announced a commercial catalog built on Nessie.[^n3]
